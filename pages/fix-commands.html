Fix Commands

Every Rackwyse finding includes an exact CLI command to fix it. No searching, no guessing — just copy, paste, and run.

How fix commands work

When you expand a finding on the dashboard, you see three tabs:

  • CLI — copy-paste command for AWS CLI, gcloud, or az CLI
  • Console Steps — step-by-step instructions for the cloud web UI
  • Official Docs — link to the relevant cloud provider documentation

CLI tab

The CLI command is pre-filled with your actual resource ID where available. Click the Copy button to copy it to your clipboard. Run it in your terminal after ensuring you have the appropriate cloud CLI installed and configured.

⚠️
Always review CLI commands before running them, especially for destructive operations like deleting volumes or snapshots. Rackwyse recommends creating a backup or snapshot before making infrastructure changes.

Console Steps tab

The Console Steps tab shows exactly where to navigate in the AWS Console, GCP Console, or Azure Portal to make the change manually. This is useful if you prefer not to use the CLI or need to verify the change visually.

Finding ownership

You can assign findings to team members and set due dates:

  1. Expand a finding
  2. Click Assign and enter the team member email
  3. Set a due date
  4. Set status to In Progress

Team members with access to the account can see their assigned findings across all analyses.

Marking findings as fixed

After applying a fix, expand the finding and change its status to Done. The confirmed savings are added to your Savings Tracker total.

Coverage

Rackwyse includes fix commands for all 99 detection rules across AWS, GCP, and Azure. Some commands include placeholder values (shown as <value>) that you need to replace with your specific resource details.

Getting fix recommendations right

Not every finding requires immediate action. Before running a fix command:

  • Verify the finding — confirm the resource is genuinely unused or oversized
  • Check for dependencies — ensure nothing relies on the resource
  • Time the change — schedule changes during low-traffic windows
  • Snooze if needed — if you need more time to investigate, set the finding to Snoozed
